# 05 — Modelo pedagógico del mundo

## Propósito

Definir cómo se aprende dentro de Manual de Vida sin convertir el proyecto en una colección de materias, lecciones o recompensas.

Manual de Vida se concibe como un **mundo de aprendizaje sobre la vida**. Su unidad fundamental no es el contenido aislado, sino la experiencia que permite observar, comprender, decidir, actuar y aprender.

## Principio rector

> El mundo no debe enseñar solamente qué pensar. Debe ayudar a aprender cómo observar, preguntar, decidir, actuar y aprender de la experiencia.

## Ciclo fundamental

**Situación → Curiosidad → Exploración → Comprensión → Opciones → Decisión → Acción → Consecuencia → Reflexión → Aprendizaje**

El ciclo no representa una ley psicológica universal. Es un modelo pedagógico propio para organizar experiencias.

## 1. Situación

El aprendizaje comienza con algo que puede ocurrir en la vida real:

- una discusión;
- una decisión;
- una emoción;
- una duda;
- un problema práctico;
- una oportunidad;
- una actividad;
- un error;
- algo que despierta curiosidad.

No toda situación necesita convertirse en una lección.

## 2. Curiosidad

El sistema debe favorecer preguntas antes que respuestas automáticas.

Ejemplos:

- ¿Qué está pasando?
- ¿Qué sé realmente?
- ¿Qué estoy suponiendo?
- ¿Qué quiero descubrir?
- ¿Qué podría pasar?

La curiosidad es una puerta de entrada, no un mecanismo para aumentar artificialmente el tiempo de pantalla.

## 3. Exploración

El usuario puede explorar información, ejemplos, historias, simulaciones, objetos, conversaciones o experiencias reales.

La exploración puede ser:

- digital;
- física;
- social;
- creativa;
- experimental;
- reflexiva.

El sistema debe favorecer progresivamente la exploración autónoma.

## 4. Comprensión

La persona construye una representación más clara de lo que está ocurriendo.

Aquí pueden aparecer las distinciones fundamentales del proyecto:

- hecho ↔ interpretación;
- expectativa ↔ realidad;
- pensamiento ↔ evidencia;
- emoción ↔ acción;
- deseo ↔ necesidad;
- control ↔ no control;
- objetivo ↔ proceso;
- error ↔ aprendizaje;
- comparación ↔ contexto.

## 5. Opciones

Una vez comprendida una situación, el sistema puede ayudar a generar alternativas.

No debe presentar una única respuesta correcta cuando existen varias respuestas razonables.

Preguntas posibles:

- ¿Qué podrías hacer?
- ¿Qué otras opciones existen?
- ¿Qué podría ocurrir con cada una?
- ¿Qué información te falta?
- ¿A quién podrías pedir ayuda?

## 6. Decisión

El usuario practica tomar decisiones adecuadas a su edad y contexto.

La plataforma no debe sustituir el criterio personal ni decidir asuntos complejos en nombre del usuario.

En menores, las experiencias sensibles deberán incorporar salvaguardas y vías apropiadas de acompañamiento adulto.

## 7. Acción

Siempre que sea seguro y apropiado, el aprendizaje debe poder convertirse en acción.

La acción puede ocurrir dentro del mundo o fuera de la pantalla.

Ejemplos:

- observar algo en la naturaleza;
- preparar una comida;
- ordenar un espacio;
- hablar con alguien;
- registrar un gasto;
- construir algo;
- practicar una habilidad;
- probar una estrategia;
- hacer una pregunta;
- completar un pequeño proyecto.

## 8. Consecuencia

La experiencia debe permitir observar qué ocurrió.

No todas las consecuencias serán positivas. Un resultado inesperado o un error puede convertirse en material de aprendizaje.

## 9. Reflexión

La reflexión transforma experiencia en conocimiento personal.

Preguntas posibles:

- ¿Qué ocurrió?
- ¿Qué esperaba?
- ¿Qué pasó realmente?
- ¿Qué aprendí?
- ¿Qué me sorprendió?
- ¿Qué haría diferente?
- ¿Qué todavía no entiendo?

## 10. Aprendizaje

El resultado no debería reducirse a una puntuación.

Puede manifestarse como:

- una nueva comprensión;
- una distinción que ahora reconoce;
- una habilidad practicada;
- una estrategia probada;
- una decisión revisada;
- una pregunta nueva;
- mayor autonomía;
- un proyecto completado;
- capacidad para pedir ayuda.

## Unidades de experiencia

### Descubrimiento

Una experiencia breve que permite encontrar o comprender algo.

### Exploración

Un recorrido abierto con múltiples caminos posibles.

### Misión

Una experiencia con un propósito concreto y acotado.

### Experimento

Una situación diseñada para probar una hipótesis o estrategia y observar el resultado.

### Proyecto

Una experiencia de mayor duración en la que el usuario define, construye, revisa y completa algo.

### Conversación

Una experiencia orientada a formular preguntas, escuchar, expresar ideas y comprender otras perspectivas.

### Experiencia real

Una actividad fuera de pantalla conectada con un objetivo de aprendizaje.

Estas unidades son categorías de diseño, no necesariamente etiquetas visibles para el niño.

## Progresión

La progresión debe representar **mayor capacidad**, no mayor valor personal.

En términos generales:

**Explorar → Reconocer → Comprender → Practicar → Decidir → Crear → Enseñar/Compartir**

No todos los usuarios deben seguir exactamente la misma secuencia.

## Función del adulto

El adulto puede actuar como acompañante, facilitador o fuente de apoyo.

El sistema debe evitar convertir al adulto en supervisor permanente del comportamiento digital del niño.

## Juego

El juego es un medio, no el objetivo final.

Puede utilizarse para practicar:

- atención;
- memoria de trabajo;
- autocontrol;
- flexibilidad cognitiva;
- planificación;
- resolución de problemas;
- cooperación;
- creatividad.

Las experiencias deben adecuarse al desarrollo y permitir progresivamente que el usuario gane independencia. ## Pantalla y mundo real

Manual de Vida debe diseñarse con una regla explícita:

> **La experiencia digital debe aumentar la capacidad de vivir experiencias reales, no reemplazarlas innecesariamente.**

Una experiencia digital puede terminar con una invitación a:

- observar;
- conversar;
- construir;
- moverse;
- crear;
- cocinar;
- explorar;
- ayudar;
- investigar;
- descansar.

## IA dentro del modelo

La IA puede actuar como acompañante cognitivo:

- explicar;
- preguntar;
- ofrecer ejemplos;
- adaptar lenguaje;
- generar escenarios;
- ayudar a comparar opciones;
- proponer preguntas de reflexión;
- conectar una experiencia con conocimiento verificado.

La IA no debe:

- decidir por el usuario;
- diagnosticar;
- presentar hipótesis como hechos;
- inventar fuentes;
- sustituir profesionales;
- fomentar dependencia emocional;
- convertirse en el centro de la experiencia.

## Métrica pedagógica principal

No medir principalmente:

- minutos conectados;
- cantidad de pantallas vistas;
- cantidad de recompensas;
- sesiones iniciadas.

Investigar métricas de aprendizaje como:

- comprensión de conceptos;
- capacidad de transferencia a nuevas situaciones;
- calidad de las preguntas;
- revisión de errores;
- autonomía progresiva;
- aplicación fuera de pantalla;
- capacidad de explicar o enseñar algo aprendido.

## Hipótesis de diseño

> Si una experiencia ayuda a una persona a observar mejor una situación real, comprenderla, considerar opciones, actuar de forma segura y reflexionar sobre el resultado, entonces puede contribuir a desarrollar una habilidad para la vida.

Esta es una hipótesis de diseño, no una afirmación científica definitiva. Deberá validarse mediante investigación pedagógica y pruebas con usuarios.
