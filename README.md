# Manual de Vida

> Nombre de trabajo. El nombre definitivo podrá cambiar cuando la identidad del proyecto esté más clara.

Manual de Vida es un proyecto educativo abierto orientado principalmente a **niños y adolescentes**. Busca ayudarles a comprender mejor lo que les ocurre, desarrollar habilidades para la vida, tomar decisiones y construir autonomía.

No pretende enseñar una forma única de vivir. Busca crear un entorno donde una persona pueda **explorar, comprender, practicar, crear, equivocarse, aprender y crecer**.

## Visión

> **No queremos enseñarles cómo vivir. Queremos ayudarlos a aprender a vivir.**

La experiencia será visual, interactiva y personalizable: color, ilustraciones, historias, avatar, mascota, espacios propios, desafíos, proyectos, coleccionables e insignias podrán formar parte del sistema cuando tengan una función educativa clara.

La gamificación deberá servir al aprendizaje y no a maximizar tiempo de pantalla o dependencia.

## Áreas iniciales

- Mente y pensamiento
- Emociones
- Cuerpo y conciencia corporal
- Relaciones
- Internet y entorno digital
- Finanzas
- Identidad y dirección
- Acción, proyectos y aprendizaje

## Núcleo educativo

**Autoconocimiento → Comprensión → Decisión → Acción → Aprendizaje**

## Distinciones fundamentales

- Hecho ↔ interpretación
- Expectativa ↔ realidad
- Emoción ↔ acción
- Control ↔ no control
- Deseo ↔ necesidad
- Objetivo ↔ proceso
- Error ↔ aprendizaje
- Comparación ↔ contexto
- Pensamiento ↔ evidencia

## IA y conocimiento

La inteligencia artificial podrá formar parte del sistema, pero no será la fuente primaria de verdad.

La arquitectura prevista es:

**Fuentes confiables → conocimiento estructurado → recuperación de evidencia → motor pedagógico y seguridad → IA → experiencia del usuario**

La IA deberá estar subordinada a evidencia, diseño pedagógico, límites de edad, privacidad y seguridad.

## Acceso universal

La intención del proyecto es que el acceso educativo no dependa de la capacidad económica de la familia.

La sostenibilidad y posibles alianzas se investigarán posteriormente. El modelo no deberá depender de vender datos, perfiles, vulnerabilidades o atención de niños y adolescentes.

## Criterio de desarrollo

Cada contenido deberá distinguir, cuando corresponda:

1. evidencia disponible;
2. interpretación o hipótesis;
3. propuesta pedagógica;
4. reflexión filosófica o personal.

Los temas sensibles deberán desarrollarse con especial cuidado, fuentes trazables, revisión especializada y límites claros entre educación y atención profesional.

## Arquitectura del proyecto

La aplicación no será el punto de partida. Primero se construirá una fuente de verdad conceptual, pedagógica, documental y de seguridad. La interfaz, la IA y la lógica de producto se desarrollarán sobre esa base.

## Estado

**Fase 0 — Fundación y arquitectura conceptual.**

El repositorio es la fuente de verdad del proyecto. Las decisiones posteriores deberán poder rastrearse hasta principios, evidencia, hipótesis, experimentos o decisiones explícitas.
